# Deploying CarePurse (Google Cloud Run or Render for the backend, Vercel for the web app)

Stellar **testnet** and the VTpass **sandbox** only. Three services from one Blueprint (`render.yaml`):

| Service | Folder | What it is |
|---|---|---|
| `carepurse-gateway` | `services/gateway` | The x402 seller. Fulfils through the VTpass sandbox |
| `carepurse-mhasibu` | `packages/mhasibu` | The agent. Holds the agent wallet, asks the purse contract, pays over x402 |
| `carepurse-web` | `apps/web` | Mama's chat (`/chat`) and the demo view with the live log (`/demo`) |

## Before you start

1. **VTpass sandbox keys:** sign up at https://sandbox.vtpass.com, then Account → API Keys. Copy the **api-key**, **public-key** and **secret-key** (the last two are shown once).
2. **Wallet values** from our local `.env` (ask Rita; never paste them in chat or commit them): `GATEWAY_RECIPIENT` (public address) and `AGENT_SECRET_KEY` (Mhasibu's testnet secret).
3. **NEAR AI Cloud key** for Mhasibu's private model (optional; without it Mhasibu uses the keyword parser). Paste it as `LLM_API_KEY` on carepurse-mhasibu.

## The database (do this first)

1. Sign up at **https://neon.tech** (free; GitHub login works) and create a project, for example `carepurse`, region close to Render's (Frankfurt or US East).
2. Copy the **connection string** (it looks like `postgresql://user:password@ep-xxxx.neon.tech/neondb?sslmode=require`).
3. Paste it as `DATABASE_URL` for **carepurse-gateway** and **carepurse-mhasibu** in Render. Nothing else to set up: the table is created on first start.
4. Render generates `DATA_ENCRYPTION_KEY` on both services: every row is sealed (AES-256-GCM) before it reaches Neon. **Copy both values somewhere safe** (a password manager): without them the stored rows can't be read.

Why Neon: Render's free Postgres is deleted after 30 days (mid-December, around Demo Day); Supabase's free tier pauses after a week without use.

## Steps

1. Render dashboard → **New → Blueprint** → connect GitHub → pick `Ritapossible/CarePurse` → it reads `render.yaml`.
2. Fill in the `sync: false` values it asks for. Use placeholders for the URLs on the first pass; Render shows each service's URL (`https://carepurse-gateway-xxxx.onrender.com`) once created.
3. Then set, and redeploy:
   - gateway `GATEWAY_URL` = the gateway's own URL
   - mhasibu `GATEWAY_URL` = the gateway's URL
   - web `MHASIBU_URL` = Mhasibu's URL. `MHASIBU_API_KEY` is generated by Render on Mhasibu and copied to the web app automatically
   - web `WEB_ACCESS_CODE` (**required**) = a code for the demo link, then share `https://<web>/demo?code=<code>`. Without it the web app keeps Mama's chat closed (503), so the agent key can never be used by an anonymous visitor
4. Check: open `https://<gateway>/health`, `https://<mhasibu>/v1/status` (the only public Mhasibu route; everything else answers 401 without the key), then `https://<web>/demo?code=<code>` and send "Abeg, light don almost finish", then "1".

## Backend on Google Cloud Run

The gateway and Mhasibu run together in **one** Cloud Run service (`Dockerfile`, `deploy/cloudrun/start.mjs`): Mhasibu is public, the gateway listens only inside the container. They stay two programs, so the x402 payment between them is real. The web app stays on Vercel.

**Before you start**
1. **Google Cloud:** console.cloud.google.com → create a project (e.g. `carepurse`) → link a billing account (a card is required even for the free tier). Then **Billing → Budgets & alerts → a $5 budget** so you're told before anything costs money.
2. **Neon (free Postgres):** create a database and copy its connection string. Cloud Run's disk is wiped on every restart, so without it purses, chats and tokens are lost.
3. Have ready: the agent secret key and the demo guardian secret (your wallet note), the three VTpass sandbox keys, and the NEAR AI key.

**Deploy (in Cloud Shell: the `>_` icon at the top right of the console)**

```bash
gcloud config set project YOUR_PROJECT_ID
gcloud services enable run.googleapis.com cloudbuild.googleapis.com artifactregistry.googleapis.com secretmanager.googleapis.com
git clone https://github.com/Ritapossible/CarePurse && cd CarePurse

# Secrets you type (input is hidden; nothing is saved to a file)
for s in AGENT_SECRET_KEY TREASURY_SECRET VTPASS_API_KEY VTPASS_SECRET_KEY VTPASS_PUBLIC_KEY LLM_API_KEY DATABASE_URL; do
  read -rsp "$s: " v; echo; printf %s "$v" | gcloud secrets create $s --data-file=-; unset v
done
# Secrets generated for you
for s in MHASIBU_API_KEY GATEWAY_API_KEY DATA_ENCRYPTION_KEY; do
  openssl rand -hex 32 | tr -d '\n' | gcloud secrets create $s --data-file=-
done

# Let Cloud Run read them
PROJECT=$(gcloud config get-value project)
PN=$(gcloud projects describe $PROJECT --format='value(projectNumber)')
gcloud projects add-iam-policy-binding $PROJECT --member=serviceAccount:$PN-compute@developer.gserviceaccount.com --role=roles/secretmanager.secretAccessor

# Build and deploy (about 3 minutes)
gcloud run deploy carepurse-backend --source . --region europe-west1 --allow-unauthenticated \
  --max-instances 1 --cpu 1 --memory 512Mi --timeout 3600 \
  --env-vars-file deploy/cloudrun/env.yaml \
  --set-secrets AGENT_SECRET_KEY=AGENT_SECRET_KEY:latest,TREASURY_SECRET=TREASURY_SECRET:latest,VTPASS_API_KEY=VTPASS_API_KEY:latest,VTPASS_SECRET_KEY=VTPASS_SECRET_KEY:latest,VTPASS_PUBLIC_KEY=VTPASS_PUBLIC_KEY:latest,LLM_API_KEY=LLM_API_KEY:latest,DATABASE_URL=DATABASE_URL:latest,MHASIBU_API_KEY=MHASIBU_API_KEY:latest,GATEWAY_API_KEY=GATEWAY_API_KEY:latest,DATA_ENCRYPTION_KEY=DATA_ENCRYPTION_KEY:latest
```

- `--allow-unauthenticated` lets Vercel reach it; Mhasibu still answers only with `MHASIBU_API_KEY` (except `/v1/status`).
- `--max-instances 1` keeps one copy running, so two taps can never pay twice.

**Then**
1. Copy the service URL it prints (`https://carepurse-backend-….run.app`) and check `https://<url>/v1/status`.
2. **Vercel** (Settings → Environment Variables): `MHASIBU_URL` = that URL; `MHASIBU_API_KEY` = the generated key. To see it once: `gcloud secrets versions access latest --secret MHASIBU_API_KEY` (copy it into Vercel, then `clear` the screen). Redeploy Vercel.
3. **UptimeRobot:** one HTTP(s) monitor on `https://<url>/v1/status` every 5 minutes. Each ping is a tiny request, well inside the free tier.
4. **Updates:** after a push to `main`, run the same `gcloud run deploy …` again from Cloud Shell (`cd CarePurse && git pull` first).

**Cost:** the free tier covers the pings and normal demo use. The one thing that costs money is **leaving the demo page (live log) open for days**: its live connection keeps the server busy the whole time. Close the tab after demos; the budget alert warns you if anything adds up.

## Web app on Vercel (recommended)

The landing page, Mama's chat and the demo can run on Vercel instead of Render (faster pages, no cold start). The gateway and Mhasibu stay on Render: they hold wallets and need to stay up.

1. Vercel → **Add New → Project** → import `Ritapossible/CarePurse`.
2. **Root Directory: `apps/web`**. Vercel detects Next.js; leave the build settings as they are (`npm run build`).
3. Environment Variables (see `apps/web/.env.example`):
   - `MHASIBU_URL` = Mhasibu's Render URL
   - `MHASIBU_API_KEY` = copy it from the Render dashboard (carepurse-mhasibu → Environment). It stays on Vercel's server; browsers never get it
   - `WEB_ACCESS_CODE` (**required**) = the code for the demo link
4. Deploy, then share `https://<project>.vercel.app/demo?code=<code>`. A visitor without the code sees a box to type it.
5. Remove the `carepurse-web` service from Render (or don't create it), so only one web app holds the key.

The live log is a stream (Server-Sent Events). On Vercel a function runs for at most `maxDuration` (300 s, set in the relay route); the browser reconnects by itself, so the log keeps going.

## Sign-up with Privy

1. **dashboard.privy.io** → Create app (CarePurse).
2. **Login methods:** Email and Google on.
3. **Allowed domains:** your Vercel address (e.g. `https://care-purse.vercel.app`) and `http://localhost:3000`.
4. Copy the **App ID** (public) into Vercel as `NEXT_PUBLIC_PRIVY_APP_ID`, then redeploy. No Privy secret is needed: our server checks logins with Privy's public keys.
5. On Render (carepurse-mhasibu): `PURSE_WASM_HASH` is already in `render.yaml`. Set `TREASURY_SECRET` to the testnet wallet that hands out test USDC (the demo guardian's secret works). The agent wallet needs test XLM: it pays the fee to create each family's purse.

Try it: open `/start`, sign in, fill in Mama, check the meter (VTpass sandbox: `1111111111111`), choose Standard, approve once in Privy, get test USDC, copy Mama's link and open it on a phone.

## Keep it awake (UptimeRobot)

Add three HTTP(s) monitors, every 5 minutes: the gateway's `/health`, Mhasibu's `/v1/status` and the web app's `/`. Pause them while we build and switch them on for judging and Demo Day: Render's free plan has **750 hours a month for the whole account**, and three services awake 24/7 use them up in about 10 days (then Render suspends all free services until next month). See the README, "Hosting and keeping it awake".

## Things to know

- **Free plan sleeps** after 15 minutes idle; the first request takes about a minute. Open all three URLs a few minutes before a demo.
- **Privacy keys are automatic:** `GATEWAY_API_KEY` is generated on the gateway and shared with Mhasibu (only Mhasibu can read orders), and `DATA_ENCRYPTION_KEY` on each service. The meter/phone fingerprints on-chain are keyed from `AGENT_SECRET_KEY`, so use the same agent key as in `.env`, or run `npm run sync-purse` after changing it.
- **Set `DATABASE_URL`** on the gateway and on Mhasibu (the same database is fine). Render's free plan wipes files on every restart; with the database, orders, purchases, Mama's tokens and her chat survive. Without it they'd reset after each restart.
- **Mhasibu is not public.** Every route except `/v1/status` needs `MHASIBU_API_KEY`; only the web app's server holds it. Mama's chat and tokens are reachable only through the web app (and its access code, if set).
- **No secrets in `render.yaml`.** The gateway only needs its public address; only Mhasibu holds a secret key.
- **Testnet resets on 16 Dec 2026:** run `npm run setup`, `npm run get-usdc` and `npm run deploy-purse` locally again, then update `PURSE_CONTRACT_ID` on Render.
